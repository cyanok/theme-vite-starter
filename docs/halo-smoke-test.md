# Halo 2.26 运行时冒烟检查

本清单用于验证构建检查无法执行的 Thymeleaf 表达式、Finder 调用、评论和插件布局。每次发布前在独立测试站执行一遍；修改相应功能后重跑受影响的项目。`pnpm check`、`pnpm test:build` 和 `pnpm build` 通过不能替代本清单。

## 准备与记录

1. 使用 Halo **2.26.0** 检查最低兼容版本；如还声明支持其他版本，另记对应版本的结果。记录主题 commit、Halo 版本、浏览器版本及插件名称和版本。
2. 按 [README 的快速开始](../README.md#快速开始) 挂载、安装并启用主题，确认挂载目录名与 `theme.yaml` 的 `metadata.name` 一致。开发验证关闭 Thymeleaf 缓存（Docker 使用 `SPRING_THYMELEAF_CACHE=false`）。执行 `pnpm build`，再在 Halo 中重载主题。
3. 准备无公开文章的测试站，先完成空状态检查，再创建后续数据。仅操作专用测试数据，保留测试前的主题设置、菜单与插件状态，便于复测和恢复。
4. 打开浏览器开发者工具的 Console 与 Network，并查看本次测试时间范围内的 Halo 日志。每项均检查 HTTP 状态、实际内容和静态资源；HTTP 200 但主体缺失也视为失败。日志只记录脱敏后的异常类型、模板名和行号。
5. 在桌面宽度（例如 1280 像素）和移动端宽度（至少 375 和 320 像素）执行布局检查。用未登录窗口核对公开页面，避免将 Console 预览的结果当作公开页面结果。

记录每一项的 `通过 / 失败 / 未执行`、访问 URL、证据和备注；缺少测试数据或插件时标为“未执行”，不要勾选通过。

## 正文宽内容检查

将 [正文示例片段](fixtures/article-content.html) 粘贴到支持原始 HTML 的编辑器模式中，分别用于一篇文章和一个独立页面。发布后检查生成的正文仍保留 `width`、`height`、表格内联宽度和 `iframe`；如果编辑器清理了这些属性或标签，需通过其 HTML 功能恢复，否则没有实际覆盖该用例。

示例中的图片和视频封面使用内联 SVG，无需外部网络。视频最初只有封面，用于检查尺寸；验证播放时上传一段 16:9 的测试视频到测试站附件，为示例的 `video` 设置其 `src`。如果编辑器禁止图片的 `data:` 地址，则上传等比例宽图并替换 `src` 与 `poster`，保留声明的宽高。

- [ ] 图片宽度不超过正文；蓝色圆形保持正圆，图片高度随宽度等比例缩小。
- [ ] 视频宽度不超过正文，16:9 画面比例保持正常；设置有效视频地址后，播放和控件均可用。
- [ ] 1200 像素宽的表格在自己的区域内横向滚动，最右列“合计（最右列）”可见；表格仍保留表头和表格语义。
- [ ] 960 像素宽的嵌入页在自己的区域内横向滚动，右侧“嵌入内容最右侧”可见；固定高度没有因强行设置视频比例而被裁切。
- [ ] 键盘 Tab 能聚焦表格和嵌入的滚动区域，聚焦有可见轮廓，可用方向键横向滚动。
- [ ] 长代码只在代码块内横向滚动，长文本正常换行；整页不出现横向滚动，页头和页脚宽度不受正文影响。
- [ ] 桌面和移动端都没有正文适配脚本错误；两种页面均加载共享 `main` 入口并完成局部滚动容器初始化。

正文适配会在共享脚本加载时为 `table`、`iframe`、`object` 和 `embed` 添加局部滚动容器，保留内容原来的尺寸与语义。若实际内容使用 `object` 或 `embed`，用同样的宽度检查对应资源；这些资源的加载和浏览器支持情况需单独记录。

## 评论启停检查

选择与 Halo 2.26.0 兼容的评论插件，记录插件版本；准备允许评论的文章和独立页面。

1. 未安装或停用评论插件时访问两种页面：正文完整，不显示失效的评论控件，不出现模板异常或调用不存在组件的错误。
2. 启用评论插件，并在 Halo 的评论设置中允许评论：两种页面均能显示可用的评论区域。在测试站分别提交不同内容的测试评论；如果启用审核，完成审核后确认各评论只属于对应文章或独立页面，刷新后仍正确。
3. 在内容设置中关闭其中一篇文章或一个独立页面的评论，再检查对应页面按评论配置隐藏或禁止评论，其他允许评论的页面仍正常。
4. 停用插件后重访两种页面，再重新启用复查：正文和导航始终可用，评论区域随有效配置变化，不残留失效入口。

## 使用公共布局的插件页面

准备一个**明确使用 `layout :: html(head, content)` 契约**、兼容 Halo 2.26.0 的插件前台页面，记录插件名称、版本、页面 URL 和其模板调用依据。仅有插件前台页面但不调用该契约，无法覆盖此项；没有合适插件时标为“未执行”。契约说明见 [Halo 页面布局文档](https://docs.halo.run/developer-guide/theme/page-layout)。

- [ ] 主题重载后，Console 的页面布局状态为 `SUPPORTED`；该状态只代表静态兼容，还需检查实际页面。
- [ ] 插件页面显示插件自己的正文和标题；文档只有一个有效标题，插件的头部资源也正常加载。
- [ ] 插件页面使用当前主题的站点标题、导航、页脚和共享样式，桌面与移动端均正常。
- [ ] 临时将主题设置的自定义页脚改为唯一标记（例如 `Smoke footer`），普通文章和插件页面都显示该标记一次；恢复原设置后两处同步恢复。
- [ ] Halo 页脚注入及插件需要的资源正常，浏览器 Console 和 Halo 日志没有片段解析、表达式或资源错误。
